Por quê

Hoje a interface são quatro sistemas empilhados

Cada tela escolhe o próprio botão, modal, cinza e azul. Nada segue a marca, e parte disso está quebrada de um jeito que o usuário já vê.

4

camadas de UI: shadcn (133 arquivos), MUI (63, azul padrão), PrimeReact (13, tema índigo) e o kit V1

3

sistemas de cor misturados: ~1.900 classes da marca, ~1.970 padrões do Tailwind, ~330 hex soltos

302

classes de cor que não geram nada (81 arquivos). Spinners não giram, skeletons não pulsam, gradientes sumiram

3+

implementações por componente. Só de botão: V1, shadcn, MUI e 271 <button> soltos

Salvar

Nosso botão principal reprova no contraste: branco sobre #FF7600 dá 2,68:1 (o AA exige 4,5). Ele é usado 77 vezes.

O ModalTemplate (73 arquivos) não é um diálogo acessível: sem role="dialog", sem prender o foco e o Esc não fecha. 4 bibliotecas de ícones, toasts nas cores padrão da biblioteca, e o tema do shadcn ainda é o zinc de fábrica.

Fonte: levantamento da UI no origin/develop2

A proposta

Um design system no código, entregue em um único PR

🎨 Tokens

Cores da marca, tipografia, espaçamento, arredondamento, sombras e camadas como variáveis CSS + Tailwind. Duas camadas: primitivos crus embaixo e nomes com significado (primary, cta, success…) em cima.

🧩 Uma biblioteca de componentes

shadcn/Radix + cva em components/ui, com a cara da marca. MUI, PrimeReact, headlessui, o kit V1 e 3 bibliotecas de ícones saem.

📚 Catálogo vivo + proteções

Storybook para todos os componentes, mais testes de guarda e jsx-a11y no CI para o código não voltar ao que era.

Dentro do escopo

  • Todas as telas: site público, área do estudante, painéis administrativos
  • Correções de acessibilidade (contraste, foco, diálogos, rótulos)
  • Comportamento no celular (áreas de toque, tabelas em cards, diálogos em tela cheia)
  • Guias de escrita e de acessibilidade

Fora do escopo

  • A biblioteca no Figma (pode espelhar a spec depois)
  • Valores do modo escuro (a estrutura já está pronta)
  • Unificar as bibliotecas de gráficos (só as cores entram)
  • Publicar o Storybook (depois, quando precisar)
O código é a fonte da verdade · os tokens do dashV2 são o ponto de partida3

Duas camadas, tudo em variáveis CSS

Primitivos: só variáveis CSS, sem classes do Tailwind
--marine-900 --orange-700 --mint-400 … 8 matizes × 11 tons
  • Tudo fica em src/styles/tokens.css. O Tailwind só liga os nomes a hsl(var(--x) / <alpha>).
  • Temas reapontam os mesmos tokens: [data-theme="marine"] na home hoje, .dark no futuro. Os componentes não mudam.
  • Toasts, o seletor de datas e os gráficos leem as mesmas variáveis.
  • Nomes em inglês. Nomes semânticos nunca citam uma cor (nada de --orange-button).
  • A correção da fase 0 faz voltar as 302 classes mortas, os spinners e os gradientes.

Espaçamento · arredondamento · elevação · layout

Oficializar o que o código já faz

Espaçamento

Mantém a escala de 4px do Tailwind. Componentes usam 2–32px, o layout 40–96px. p-[48px] arbitrário fica proibido.

Raios: uma função cada

4 · chips6 · controles
8 · cards12 · diálogospílulas

Bordas, não sombras

Superfícies dentro da página ganham borda de 1px. Sombra só para o que flutua (menus, toasts, diálogos), em 3 níveis tingidos de marine.

cardmenudiálogo

Breakpoints continuam

sm 768 divide celular e desktop · md 1200 é o desktop cheio. Trocar reescreveria ~960 classes. Atenção: o nosso sm é o md do Tailwind.

Tokens de layout

Margens laterais 16/24/32 · larguras prose-content 720, form 560, page 1200 · size do Dialog 400/560/800 · --header-h substitui 17 números mágicos

Camadas de z-index com nome

base · raised · sticky · header · overlay · popover acima dos diálogos · toast. Chega de z-[1400].

Guias

Como escrevemos, e como tudo precisa funcionar para todos

✍️ Tom de voz

  • Próximo, com “você”
  • Só a primeira letra maiúscula
  • Botões: verbo + objeto (“Excluir prova”, nunca “OK”)
  • “!” só para comemorar
  • Datas e números no formato brasileiro

⚠️ Erros

  • O que aconteceu + o que fazer
  • Erro de campo embaixo do campo, nunca em toast
  • Erro que trava a tela: Alert na página + tentar de novo
  • Sem códigos, sem culpar o usuário

♿ Acessibilidade

  • Contraste AA, mínimo de 12px, foco visível
  • Títulos em ordem, controles com rótulo
  • Nada de div clicável
  • Respeita quem prefere menos movimento
  • jsx-a11y no CI

📱 Celular

  • Áreas de toque de 44px
  • Formulário em uma coluna, barra de ação fixa
  • O teclado certo (inputMode)
  • Nada que dependa de passar o mouse

As regras de uso numa página só: um cta por tela · bordas vs sombras · badge de ponto vs tinta · prose vs body · uma só cor de texto secundário · asterisco nos obrigatórios · toast de erro fica na tela · só abas sublinhadas · mínimo de 12px.

Catálogo e proteções

Storybook para ver, testes para manter

📚 Storybook 10.6

  • Todo componente do ui tem story para cada variante e estado (obrigatório)
  • Autodocs, controles, painel axe
  • Barras: 390/768/1200 e data-theme
  • MDX: fundamentos + guias
  • A vitrine continua para as telas de funcionalidade

🛡️ Teste de guarda

  • Sem cores ou tamanhos antigos
  • Sem [#hex], [Npx] ou z-[N] arbitrários
  • Sem imports proibidos (MUI, PrimeReact…)
  • Nenhum arquivo novo nas pastas atômicas
  • Nenhum componente sem stories
  • Zero tolerância a partir do merge

✅ Também no CI

  • Teste de contraste: todo par de tokens conferido com a conta do WCAG
  • Stories renderizadas como testes rápidos
  • build-storybook quando o design system muda
  • ESLint consertado (hoje quebrado no develop) + jsx-a11y

Onde fica: components/ui (componentes + stories) · styles/tokens.css · tailwind/type-scale.js · lib/palette.ts · design-system/ (guardas, teste de contraste, docs) · .storybook/. A tabela e o badge do dashV2 vão para o ui, e o template de listas fica onde está, usando o design system.

Migração

Um PR, dez commits em ordem, cada um passando

~519 de 1.327 arquivos. Merge sem squash, para que qualquer passo possa ser localizado com bisect ou revertido sozinho. Rebase diário, os codemods rodam de novo, e um congelamento de UI de 2–3 dias para o QA final.

1Correção da fase 0Voltam as classes mortas, os spinners e os gradientes
2Tokenstokens.css, mapa do Tailwind, plugin de tipografia, fontes
3Lint e guardasESLint consertado, jsx-a11y, guarda (catraca), contraste
4Storybookconfiguração + docs MDX
5Componentes do uicom stories; DataTable vem do dashV2
6Varreduras com codemodcores, tamanhos, raios/z, ícones, um commit cada
7Famílias de componentesButton, modais, MUI, cada tela com DataGrid…
8Divisão do dashV2template sobre o ui, tokens.ts removido
9Camada da hometemas, hero, faixa
10LimpezaV1 apagado, dependências removidas, guarda em zero

Codemods

Uma tabela de mapeamento (classe antiga → token) fica na spec. Casos ambíguos ganham /* ds-review */ e são resolvidos à mão. O CI falha enquanto sobrar algum.

Verificação

CI · capturas de antes e depois de todos os estados da vitrine em 390 e 1280 · um checklist em homologação com os fluxos principais de estudante, admin e público.

Regra de escopo

Paridade + as melhorias já decididas, só isso. Bugs encontrados viram issue, não correção. Testes são adaptados, nunca apagados. Para voltar atrás: reverter um passo ou o merge.

Riscos

O que pode dar errado, e o que fazemos a respeito

RiscoComo mitigar
Um PR de 519 arquivos não dá para revisar linha a linhaUm tema por commit, codemods revisados como padrão, comparação de capturas de tela em vez de diff de classes, casos ambíguos marcados
A branch fica desatualizada (~12 commits/dia no develop)Rebase diário, as varreduras são scripts que rodam de novo, congelamento curto só no fim
Regressões de comportamento (DataGrid → DataTable, modais → Radix)Um commit por tela com DataGrid, testes existentes adaptados mantendo as verificações, fluxos ★ do checklist de homologação
Usuários percebem que toda tela mudouAs mudanças são de propósito (contraste, foco, celular); um aviso de “o que mudou” para quem coordena os cursinhos
Algo quebra em produçãoMerge commit: git revert de um passo ou do merge inteiro
O código voltar a se desviar depois do mergeGuarda em zero, jsx-a11y como erro, stories obrigatórias, teste de contraste
